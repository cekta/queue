## Описание пакета

**CEKTA/QUEUE** — это легковесный пакет абстракции для реализации классической очереди задач (**FIFO** — First In, First
Out).

> ⚠️ **Важно:** Данный пакет реализует паттерн «Очередь задач» (Task Queue) и **не является** шиной данных (Message
> Bus / Event Bus).

### Ключевые отличия от шины данных (Message Bus)

1. **Один обработчик на одно сообщение (Point-to-Point):** Каждое сообщение из очереди обрабатывается ровно одним
   воркером. В отличие от Message Bus, где на одно событие (Event) может среагировать множество независимых
   сервисов-подписчиков (паттерн Pub/Sub), здесь задача предназначена только для одного исполнителя.
2. **Удаление после обработки (Transient Storage):** В классической очереди сообщение удаляется (или помечается
   выполненным) сразу после успешного подтверждения (ACK) воркером. Оно не хранится в шине для других потенциальных
   получателей.
3. **Гарантия выполнения (Targeted Execution):** Очередь создается под конкретное целевое действие (например, «отправить
   email» или «сгенерировать отчет»). В Message Bus отправитель не знает, кто, когда и сколько сервисов отреагируют на
   его событие.

### Поддерживаемые типы хранилищ (Драйверы)

Пакет предоставляет единый интерфейс (инвариант), что позволяет гибко менять бэкенд очереди без изменения бизнес-логики
приложения. Очередь может быть реализована на базе:

* **Реляционных СУБД (РСУБД):** `PostgreSQL`, `MySQL` (оптимально для простых задач или транзакционных цепочек).
* **In-Memory хранилищ:** `Redis` (высокая скорость, низкая задержка).
* **Специализированных брокеров очередей:** `RabbitMQ`, `Kafka`, `Beanstalkd` (для высоконагруженных и сложных систем).
* **Гибридных решений:** Схема, при которой история задач, логи и мета-информация сохраняются в РСУБД, а оперативная
  очередь для быстрой раздачи воркерам крутится в In-Memory или брокерах.
